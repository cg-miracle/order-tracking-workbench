# 阶段 3 前端审核

状态：已实现并验证，等待用户审核。未进入真实物流阶段，未自动提交或推送。

## 页面

- /：订单列表，展示公司、订单号、日期、收件人、商品行数、包裹数、状态和总额。
- /orders/:id：订单详情，包含商品表格、对应包裹、收货信息、不含税单价及行小计、GST、运费与总额。
- 商品使用中性 SVG 药瓶占位图，金额仅格式化后端结果，不在浏览器重复计算。
- 每个包裹显示承运商与单号。物流独立请求，当前显示未实现，不生成状态或更新时间。
- 支持列表刷新、物流刷新、加载占位、错误重试、空列表、未知订单和未知页面。
- 不完整订单逐行显示问题，无法计算金额显示 Unavailable，不把缺失资料当作零。
- 所有页面和错误提示采用英文，README 为中文。

## 结构与排版

API 客户端集中 HTTP 状态处理和超时；TanStack Query hooks 管理服务端状态，选中订单由路由决定。
组件按订单列表、详情、复用面板和格式化工具组织。MUI 主题集中管理样式，代码按逻辑组保留空行。

受控后端由共享 TypeScript 契约约束，前端不重复逐字段校验同一内部响应。
API 失败不会静默返回空数组，404 与连接失败分别展示。

## 已验证

- 37 个测试通过：其中前端 8 个，覆盖列表到详情、直接进入、物流失败隔离、加载、失败重试、空列表、404、不完整订单和未知页面。
- typecheck、lint、format:check 与生产构建通过。
- 实际 Edge 浏览器：列表点击第二笔订单，直接详情刷新、未知订单提示及物流 HTTP 503 时保留订单内容均通过。
- 桌面 1440px 和手机 390px 截图已检查，无浏览器运行错误。
- 手机文档宽度与视口均为 390px，没有整页横向溢出；商品表格内部可横向滚动查看数量和价格，并有可见提示。
- 产品图片占位已记录，不添加真实照片或医疗建议。

## 启动与下一步

在项目根目录执行 npm run dev，访问 http://127.0.0.1:5173。
生产执行 npm run build 后 npm start，默认 http://127.0.0.1:3001。
验收时默认端口被占用，因此另启 3002 进行浏览器检查，不改动默认配置，不关闭其他已有服务。
