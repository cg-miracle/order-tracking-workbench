# 阶段 1 数据检查报告

状态：数据整理完成，等待用户审核；未实现后端业务或物流查询。

## 来源与匹配

通过题目指定查询网站实际执行只读查询，表名为 product_list，SKU 字段为 SKU。
首次照示例使用 sku_code 时返回 0 行，确认真实字段后重新查询返回 9 行。
仅保存最终成功查询结果，来源、查询及抓取时间见 data/source-metadata.json。

题目 2 个订单、9 条商品行、3 个包裹已分别整理。
9 个唯一 SKU 全部匹配，无重复 SKU、缺失名称、缺失价格、非法数量或跨订单包裹引用。
金额不预计算、不硬编码。报告不含客户联系方式和接口凭据。

## 字段与单位

| 源字段                  | 标准字段                 | 处理                                 |
| ----------------------- | ------------------------ | ------------------------------------ |
| SKU / ProductName       | sku / name               | 去除首尾空白                         |
| Description             | description（可选）      | 单独的句点视为无有效描述，不自行补写 |
| RRP                     | rrpAud                   | 原始字符串，AUD 含 GST               |
| weight                  | weightKg                 | g 除以 1000                          |
| length / width / height | dimensionsCm             | mm 除以 10                           |
| volume                  | volumeCm3                | mm³ 除以 1000                        |
| Volumetric_GrossWeight  | sourceVolumetricWeightKg | kg 原值，与实际重量分开              |

原始返回有 26 个字段，均保存在 raw 文件。标准产品仅选取本项目所需字段。
Size 没有明确单位，不标准化；Date 无时区，不转换成 UTC；ETA 不作为物流数据。

## 数据质量与处理决定

- LELCBD100、HARNIG、AURPUR10 的 Description 为“.”，标准数据省略描述，后续界面可显示名称。
- HALGEO15 描述结束于“<0”，疑似源文本截断；原样保留并标记，不推断缺失文字。
- MCMW10 名称尾部空白已去除。
- 8 条 SPU 为空；非本项目匹配依据，不补值。
- 6 条 ETA 为 nullDays，其余是 0Days 或 10Days；不将其当作实时运输预计到达时间。
- Spectrum 的 N/A、PlantSpecies 的 C37 等值不解释为业务事实，原样存档。
- AURPUR10 的实际名称为 Purple Raine THC18% 15g；不能从 SKU 后缀 10 推断规格为 10g。
- 所有 9 条长宽高乘积与源 volume 一致，单位转换后数值一致。
- 体积重与实际重量不一致，无法确认承运商计费除数；后续运费不得直接混用。
- 原始药品描述只作来源文本，不补充医疗建议；前端以普通文本渲染。
- 订单状态来自题目，不代表当前物流实时状态。

## 文件结构与发布边界

data/orders.json：订单头、recipient 结构化地址和 items（id、sku、quantity、shipmentId）。
data/shipments.json：id、orderId、carrier、trackingNumber。
data/products.json：标准产品；金额字符串，重量和尺寸数值，description 可选。
data/raw/product-list-response.json：未改写的产品查询 JSON。
data/source-metadata.json：查询来源与转换规则。

订单样本含题目提供的联系人、地址和单号，为实现任务保留，但不是脱敏数据。
本阶段不提交 Git、不推送 GitHub；最终公开发布前应确认题目允许公开样本个人信息，或以明确标注的脱敏样本交付。
不复制包含凭据的评估原件到仓库。

运行 npm run data:check 检查重复值、匹配、必填字段、单位转换、体积一致性、数量和包裹归属。
通过后停下审核；下一阶段才实现后端匹配、金额计算和接口。
