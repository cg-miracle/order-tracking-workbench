# 阶段 2：后端审核说明

## 已实现

- Zod 在服务启动时读取并校验本地订单、产品和包裹 JSON。
- 结构错误、重复 ID、重复 SKU 和孤立包裹阻止启动；非法数量、无效价格、SKU 缺失、商品引用不存在或跨订单包裹作为订单行问题返回。
- 每行计算后舍入到分，汇总小计后计算 GST，decimal.js 使用 ROUND_HALF_UP；所有金额通过十进制字符串返回。
- 不完整订单的汇总金额为 null，不展示免费商品或伪造完整总额。
- 数据在启动时加载；修改 JSON 后重启服务生效。没有增加数据库、写接口或额外 UI。
- 物流接口当前明确返回 not_implemented，没有访问承运商或生成物流事件。
- 页面和面向界面的接口提示使用英文，中文 README 保留。

## 接口

GET /api/orders：{ orders: OrderSummary[] }，包含订单摘要、商品行数、包裹数与金额。
GET /api/orders/:id：OrderDetail，包含收货人、商品匹配、金额、issues 和 shipments。
GET /api/orders/:id/tracking：{ orderId, shipments: TrackingResult[] }。
后两个接口订单不存在返回 HTTP 404；长度超过 128 的订单 ID 返回 400。

共享结构见 packages/contracts/src/index.ts。
商品行 quantity 输入允许 unknown 以报告非法数量；响应规范化为 number 或 null。
Product 的 rrpAud 保留原始价格，invalid_price 时不可当作可用金额使用。
totals.status 为 complete 或 incomplete；issues 含 itemId、code 和英文提示。
shipping 为 0.00，来源 not_implemented，不表示承运商免费配送。

## 样例金额与舍入

| 订单              | 不含税小计 | GST    | 运费 | 总额 AUD |
| ----------------- | ---------- | ------ | ---- | -------- |
| PO-20251130-00072 | 1937.28    | 193.73 | 0.00 | 2131.01  |
| PO-20251203-00046 | 1504.55    | 150.46 | 0.00 | 1655.01  |

按已约定规则，含税价除以 1.10 时保持内部精度，乘数量后才将每行小计舍入。
逐行舍入后汇总并计算 GST，样例总额比 RRP 乘数量直接求和各高 0.01。
这属于所选舍入政策的差异，不增加或隐藏调整行；显示单价只供展示，不作为行金额计算输入。
